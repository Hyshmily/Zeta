# Removal of key normalization, value codec, fluent API and compact report encoding

Four mechanisms are deleted outright with no compatibility shims: key `normalize` (`CacheKeysPolicy.normalizeKey`, `strip-query` config, `HotKeyCache`/`RuleService` call sites — keys are now used exactly as passed, the physical key is the caller string), the L1 value codec (`CacheCompressor` SPI, `Lz4CacheCompressor`, `lz4-java` dependency, all `wrap`/`unwrap` call sites — values are stored as passed, the `IOException` self-heal path is gone), the fluent API (`ZetaReadQuery`/`ZetaWriteCommand`/`CacheMode` plus `Zeta.read()`/`write()` — callers compose `get`/`put` directly), and the compact report wire format (`ReportMessageCodec`, `CompactAwareReportMessageConverter`, `report-encoding` config — reports are Jackson JSON only, receivers no longer sniff the `0x5A` magic). A fifth mechanism deleted in the same sweep is the **prefix loader registry** (the registry half of ADR-0070): `ZetaLoaderRegistry`, `PrefixRoutedLoader`, `ZetaLoadingSpec` and the no-reader `get` overloads they served are gone — every read carries its loader/reader at the call site (or through the `ZetaCache` build-time registered loader); ADR-0070's cache-customizer half (`ZetaCacheCustomizer`) remains in force.

## Considered Options

Keep each as an SPI with a no-op default (the PLAN-v2 A19 shape for the compressor, dual-format decode for reports, `stripQuery=false` baseline for keys, thin fluent sugar over policies). Rejected: every shim is a second behavior to test, document and keep compatible across rolling upgrades, while none of the four is load-bearing — normalization is business semantics that belongs to callers, the L1 already stores live object graphs for all non-`String`/`byte[]` types, the fluent builders duplicate `get`/`put` composition, and JSON reports are small enough next to the batching/BBR budget.

## Consequences

Keys containing `?` are now distinct physical keys (previously truncated when `strip-query` was on); stored `byte[]` payloads that used to carry the 1-byte codec flag are read as-is after upgrade (a rolling deploy mixing old writers and new readers serves flag-prefixed bytes once per entry until TTL expiry — bounded by the hard TTL); `compact`-encoded in-flight report bodies fail JSON decode and are discarded like any poison message; `Zeta.read()`/`write()`, `CacheCompressor`, `ReportMessageCodec` and `zeta.local.cache-key.strip-query` / `zeta.local.report-encoding` references break at compile/bind time; `ZetaLoaderRegistry`/`PrefixRoutedLoader`/`ZetaLoadingSpec` references break at compile time (ADR-0070's registry half is superseded by this ADR). Supersedes the deletable halves of ADR-0015 (compression centralization) and ADR-0074 (compact encoding).
